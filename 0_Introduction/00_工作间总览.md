## 一、核心理念（Edius 哲学延续）

> 参考使用者从 Edius 学到的思想——**软件/代码与用户数据分离，个性化设置与素材各归其位**。

| 概念 | 对应位置 |
|:---|:---|
| 软件本体（代码归代码） | WSL 内 Hermes 等智能体运行环境 |
| 个性化设置 | `1_Memory/` |
| 素材库/项目 | `2_Projects/`（智能体互访共享，主战场）|
| 工程记录 | `4_Logs/`（WorkingLog & MaintainLog）|
| 成品输出 | 生成的文档/书籍/交付物 |

**变化**：原"每个智能体一个独立工作间（Studio for Hermes / Workbuddy / …）+ MeetingRoom 会议室 + Harness 模板" 已合并统一。**编号体系仅供使用者（人）搜寻索引，智能体靠文件名检索，不受编号限制。**

## 三、各目录用途细则

| 目录 | 用途 | 访问 | 归属规则 |
|------|------|------|---------|
| `0_GithubCode/` | 共享代码/技能库（内部 1_Toys/2_Codes/3_Skills/4_List）| 全员读，**登记责任人：协调者** | 含代码进 2_Codes，SKILL.md 进 3_Skills/Installed |
| `0_Introduction/` | 说明书：总览/协作/日志规范 + 各智能体专属入门 | 说明文档由轮值管理员维护，其余只读 | 定稿文档带版本号 |
| `1_Memory/` | 角色设定、个人信息、设备配置、工作纪律、项目清单 | 各自读写自己的角色文件；公共模板只读 | 角色文件按 `<智能体名>` 子目录区分 |
| `2_Projects/` | 所有项目工作区（实际干活主战场）| **全员可读/可拷贝**；新建/删除目录需登记 | 新产出默认 `2_Projects/<项目名>/` |
| `3_MeetingRoom/` | 公共公告/讨论/信件/结论 | **全员可读可写（公共透明）** | 讨论文件、信件按规范命名，定稿移 Conclusions/ |
| `4_Logs/` | 日志（WorkingLog 每日 / MaintainLog 系统）| 本人追加自己的日志，他人只读 | 文件名 `WorkingLog_YYYY-MM_<前缀>.md` |

---

## 四、归位规则（新产出默认路径）

1. **新项目/新文档** → 默认 `2_Projects/<项目名>/`，不在根目录散放。
2. **各智能体的新产出** → 一律写入共用工作间 `2_Projects/<项目名>/`，不再写入旧 Studio 空壳。
3. **新增项目命名** → 见名知意 + 唯一性（新建前查 `目录登记表`），防重复目录。
4. **脚本/技能** → 有代码的进 `2_Projects/<SkillName>/`，SKILL.md 进 `0_GithubCode/3_Skills/Installed/`。
5. **敏感文件（账号/密钥）** → **严禁入公共区**，各智能体私有区自管。
