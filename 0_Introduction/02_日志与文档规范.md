# 02_日志与文档规范

> **文档版本**：v1.0-draft（协调者起草稿，待助理智能体复核、使用者终审）
> **生效日期**：待定稿
> **适用对象**：所有共用工作间的智能体（协调者/助理智能体/业务智能体等）与使用者
> **目的**：统一日志格式、目录命名、目录登记表与文档 changelog 模板，保证长期一致、可追溯、防重复。

---

## 一、日志规范

### 1.1 结构

```
4_Logs/
├── WorkingLog\          # 每日工作日志
│   └── WorkingLog_YYYY-MM_<前缀>.md   # 按月滚动
└── MaintainLog\         # 系统/维护日志
    └── MaintainLog_YYYY-MM_<前缀>.md  # 按月滚动
```

### 1.2 命名格式（统一）

- **前缀**：作者智能体 `[协调者]` / `[助理智能体]` / `[业务智能体]` / `[Pi]` / `[使用者]` 等。**前缀须与角色名一致**，便于跨文档追溯。
- **按月滚动**：`WorkingLog_2026-08_[协调者].md`（单文件避免无限膨胀，便于按月归档）。
- **可选速记行**：日志正文可含 `[前缀] YYYY-MM-DD HH:MM | 事项 | 结论/产物路径` 用作索引，但**主模板见 1.3**。

### 1.3 工作日志条目模板（主模板，每日一条）

```markdown
## YYYY-MM-DD

- 会话概要：核心事件
- 新增/变更要求：新偏好、规则
- 待办：未完成事项
- 今日自评：完成度 / 困惑点 / 明日重点 / 异常标记
```

> 注：以上节式为主体；如需流水索引可再加速记行，两者并存时以分节为纲。

### 1.4 维护日志条目模板

```markdown
# 维护日志 - YYYY-MM-DD

## <变更标题>
### 问题描述
### 处理过程
### 最终结果
### 遗留/注意
```

### 1.5 留存与归档

- 运行日志保留不少于 **6 个月**。
- 过期/已结事项由公共区管理员按月归档压缩，避免长期堆占。
- 存档惯例：旧方案备份到 `3_MeetingRoom/Archive/`，加版本号+描述后缀（如 `_v1.0_原方案`）。

## 二、目录命名规范

### 2.1 命名三原则

1. **见名知意**：用项目名而非随意代号。
2. **唯一性**：新建前先查 `目录登记表`，禁止静默新建第二个同名目录。
3. **带归属**：需区分时加 `<项目名>_<负责人>` 或日期后缀。

### 2.2 编号体系（仅供使用者检索）

编号便于人按习惯搜寻，**智能体靠文件名检索，不受编号限制**：

| 编号 | 目录 | 用途 |
|------|------|------|
| 0_ | GithubCode / Introduction | 共享代码库 / 说明书 |
| 0_GithubCode 内部 | `1_Toys` / `2_Codes` / `3_Skills` / `4_List` | 工具 / 代码 / 技能 / 清单 |
| 1_Memory | 角色设定 | 个性化 |
| 2_Projects | 项目主战场 | 核心 |
| 3_MeetingRoom | 公共讨论公告 | 协作 |
| 4_Logs | 日志 | 记录 |

> ⚠️ `0_GithubCode` 内部子目录（1_Toys/2_Codes/4_List）为**该目录专属编号**，与顶层同名目录无关，勿混淆（如 `0_GithubCode/2_Codes` ≠ 顶层 `2_Projects`）。顶层 `3_Skills` 不存在，仅 `0_GithubCode/3_Skills` 特有。

> 废弃目录：`3_Tools`（并入 GithubCode）、`Harness`、`Library`、`VideoLibrary`、`MeetingRoom`（已并入 3_MeetingRoom）。

## 三、目录登记表

### 3.1 位置
`2_Projects/_目录登记表.md`（独立登记表文件，新建目录即登记；**不用项目自带 Readme.md**，避免混淆）。

### 3.2 登记表格式

```markdown
## 目录登记表

| 项目名 | 负责人 | 状态 | 创建日期 | 最近更新 | 说明 |
|--------|--------|------|---------|---------|------|
| Project2：英语拼读 | 协调者 | 进行中 | 2026-08-13 | 2026-08-15 | 音标拼读教学工具 |
| 气象与世界 | 协调者 | 研究 | 2026-06-01 | 2026-08-01 | 气象→经济推演 |
```

### 3.3 规则
- **新建项目** → 建目录时同步登记一行。
- **删除项目** → 删除目录时同步移除登记行，并在 changelog 记录。
- **状态字段**：`进行中 / 研究 / 已完成 / 待归档`。

## 四、文档 changelog 模板

所有正式文档（`0_Introduction/` 下的说明类、定稿类）末尾含修订记录：

```markdown
## 修订记录

| 版本 | 日期 | 作者 | 说明 |
|------|------|------|------|
| v1.0 | YYYY-MM-DD | 作者 | 初稿 |
| v1.1 | YYYY-MM-DD | 作者 | 变更说明 |
```

**规则**：
- 首版 v1.0；每次实质修改递增小版本；重大重构升大版本（v2.0）。
- 文档头部标 `版本 + 生效日期 + 适用对象`。
- 被多智能体长期引用的规范类文档，必须带 changelog，防"改了不知、引用旧版"。

## 五、文档模板速查
