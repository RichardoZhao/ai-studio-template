# 设计理念 — 工作间体系的思想源起

> **本文档定位**：工作间体系的设计白皮书，解释"为什么这么建"。
> **演进说明**：本文档随工作间结构演进多次更新。当前版本对齐新版共用工作间结构（见 `00_工作间总览.md`）。早期"Studio for Hermes 单体结构 + Mailbox + Harness 模板"已合并废弃。
> 文中智能体名、路径为示例，使用时替换为你的实际配置。

---

**核心理念**

借鉴使用者从 Edius 学到的经验——**软件/代码与用户数据分离原则**：

> 使用者原话："读书的时候我不懂软件，6年前使用 Edius 剪辑时，才明白——Windows 在安装软件时，软件本体放在 Program Files 里面，个性化设置放在用户目录下面。剪辑视频要有素材、有工程记录、最后才有成品输出。这些又是默认放在系统文档这个文件夹里面。所以软件的使用包括以下几个部分：软件本体、个性化设置、工程文件（包括素材文件和成果输出）、工作日志（工作进度）、维护日志（升级、崩溃等）"

| Edius | → | 对应到这里 |
| --- | --- | --- |
| Program Files（软件本体） | → | 智能体的安装位置（代码归代码） |
| 用户设置（个性化） | → | **1_Memory/** |
| 素材库 | → | **2_Projects/**（多智能体互访共享） |
| 日志 | → | **4_Logs/WorkingLog & MaintainLog/** |
| 成品输出 | → | **2_Projects/{项目名称}/**（共享） |

## 一、工作间目录结构（现行）

```
AI_Studio/
├── 0_Introduction/      # 说明书（总览/协作/日志规范/设计理念）
├── 1_Memory/            # 个性化设置（角色设定/个人信息/工作纪律）
├── 2_Projects/          # 项目主战场（所有智能体共用）
├── 3_MeetingRoom/       # 公共讨论与公告（Bulletin/Discussions/Letters/Conclusions/Archive）
├── 4_Logs/              # 日志归档（WorkingLog / MaintainLog）
├── 5_Notes/             # 笔记与剪藏（个人知识库）
├── ToolCode/            # 可复用脚本库（01_文件与文档 … 05_系统与环境）
├── SkillsLib/           # 共享技能库（中文分类 + _备选 + 总索引）
└── GithubRepos/         # 第三方整包仓库（只读、不改造）
```

> 编号体系（0-5）仅供使用者（人）检索索引，智能体靠文件名检索，不受编号限制。
> 三库（ToolCode / SkillsLib / GithubRepos）为共享资源库，与工作间同级、无编号前缀。

## 二、各文件夹用途

| 文件夹 | 存什么 | 谁管 |
| --- | --- | --- |
| ToolCode/ | 可复用脚本（按 01–05 分类） | 登记责任人：协调者 |
| SkillsLib/ | 共享技能（中文分类；低频放 `_备选/`） | 登记责任人：协调者 |
| GithubRepos/ | 第三方整包仓库 | 只读；登记责任人：协调者 |
| 0_Introduction/ | 说明书、规范 | 维护人维护，其余只读 |
| 1_Memory/ | 角色设定、个人信息、工作纪律 | 各自维护角色文件，公共模板只读 |
| 2_Projects/ | 各项目原始资料、素材、中间文件、成品 | 按项目分类，全员可读可拷贝 |
| 3_MeetingRoom/ | 通信记录、公告、讨论、结论 | 公共透明，全员可读写（公告板除外） |
| 4_Logs/WorkingLog/ | 每日工作日志 | 每天写一条 |
| 4_Logs/MaintainLog/ | 系统更新、报错记录、自检报告 | 出问题时写 |
| 5_Notes/ | 笔记、剪藏、研究资料 | 各自维护；敏感资料不入库 |

## 三、多智能体互访规则（四层权限）

共用工作间采用四层权限模型（详见 `01_协作与互访规范.md`）：

| 层级 | 目录 | 权限 |
| --- | --- | --- |
| 公共区 | 2_Projects/、3_MeetingRoom/（除公告板） | 全员可读/可拷贝；新建删除需登记 |
| 共享只读区 | ToolCode/、SkillsLib/、GithubRepos/ | 全员可读；新增登记 |
| 个人区 | 4_Logs/、5_Notes/、各自角色设定 | 本人追加写入，他人只读 |
| 公告区 | 0_Introduction/、Bulletin.md | 只读（维护人维护） |

---

## 四、文件命名规范

1. 文件夹首字母大写（使用者习惯）
2. 日志文件：`YYYY-MM-DD.md` 或 `WorkingLog_YYYY-MM_[前缀].md`
3. 通信文件：`AgentA vs AgentB (YYYY-MM-DD).md`
4. 正文用中文，文件名可用英文

---

## 五、三不原则

- **不重装**：软件没崩溃就修，非必要不重装
- **不污染**：各项目素材不交叉混放
- **不啰嗦**：文件命名简洁，一眼看懂放什么

## 六、日志规范（SRE 级别）

日志体系仿照站点可靠性工程（SRE）思想设计，将智能体的日常运作当作生产环境来管理。

| 日志类型 | 存什么 | 谁写 | 用途 |
| --- | --- | --- | --- |
| WorkingLog/（工作日志） | 每天干了什么、新增需求、待办 | 智能体·每晚收工 | 短期记忆索引，按日期回溯 |
| MaintainLog/（维护日志） | 系统变更、报错、配置修改、升级 | 智能体·出问题时 | 排错字典，5分钟定位 |

### 工作日志模板

```markdown
# 工作日志 - YYYY-MM-DD

## 会话概要
1. 核心事件列表（按时间顺序）

## 新增/变更的要求
- 用户今天提出的新规则、偏好变更

## 待办
- [ ] 待完成任务

---
📊 今日自评
- 完成度: XX%
- 困惑点: 今天遇到的不确定问题
- 明日重点: 明天优先做的事
- 异常标记: 报错/掉线/异常行为记录
```

### 维护日志模板

```markdown
# 维护日志 - YYYY-MM-DD

## 变更标题
### 问题描述
### 处理过程
### 最终结果
```

## 七、智能体通信规范

- 通信记录统一放 `3_MeetingRoom/`（Bulletin 公告板、Discussions 讨论、Letters 信件、Conclusions 结论、Archive 归档）
- 主动定期检查，不等使用者提醒
- 写信格式：分隔线 + 署名 + 时间 + 正文
- 不删除对方通信内容，只追加
- 单文件超 300 行新建续写
