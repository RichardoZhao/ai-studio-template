# 05_注入层对齐指引

> **文档版本**：v1.0（助理智能体起草，待使用者终审、协调者/业务智能体确认各自接入情况）
> **生效日期**：待定稿
> **适用对象**：所有共用工作间的智能体（助理智能体/协调者/业务智能体/编码智能体等）
> **目的**：解决"外部记忆系统再完善，进不了智能体内部记忆就不生效"的问题，规定各智能体内部记忆与工作间事实源的统一对接方式。

---

## 一、问题定义

智能体每个会话都是"失忆重启"，**只有内部记忆（系统提示词注入层）的内容必然在场**；工作间 `1_Memory/` 的内容再完整，若注入层没有指向它，智能体就不会主动读取，导致：

- 各智能体按旧信息、旧路径各自为政
- 工作间规范"写在纸上"，落不到行为上
- 内部记忆与工作间内容重复维护，出现版本漂移（已发生：改名遗留、版本号不一致）

---

## 二、解决方案：薄注入层 + 厚事实源

### 1. 分层结构

| 层 | 位置 | 职责 | 特性 |
|:---|:---|:---|:---|
| **薄注入层** | 各智能体内部记忆（如 WorkBuddy 的 `~/.workbuddy/` 三件套、Hermes 的启动配置、业务智能体的 System Prompt） | 只放三样东西：①身份速记 ②强制启动指令 ③指向工作间的指针 | 平台保证注入，100% 到场 |
| **厚事实源** | `1_Memory\` + `0_Introduction\` | 全部角色、纪律、项目、个人信息 | 跨智能体共享，唯一事实源，修订走正式流程 |

### 2. 核心原则

1. **单一事实源**：注入层不重复维护工作间已有的内容（项目清单、设备环境、文档规范等一律以 `1_Memory/` 为准）；两处冲突时，以工作间文件为准。
2. **强制启动**：注入层必须包含硬性指令——会话启动先读 `1_Memory/` 全部公共文件 + `0_Introduction/00~02` + `3_MeetingRoom/Bulletin.md`，未执行不得开始任务。
3. **纪律优先于效率**：启动多花一两分钟是可接受代价，换取所有智能体行为一致。
4. **注入层保持薄**：越薄越好维护、越不容易漂移。判断标准：删掉这段内容后工作间文件里能否找到——能找到就不该留在注入层。

### 3. 例外：智能体专属规则

仅针对某智能体自身运行环境的规则（如 WorkBuddy 的插件管控、Python 环境约定），其他智能体用不上，**允许保留在各自注入层**，不强行迁入共享区。

## 四、注入层模板（通用）

各智能体将以下结构翻译为自己的配置格式：

```
【身份速记】我是谁、角色一句话、称呼使用者：潘德先生（使用者）

【强制启动指令】
每次会话启动后、开始任何任务前，必须：
1. 读取 1_Memory\ 全部公共文件
2. 读取 0_Introduction\00~02
3. 读取 3_MeetingRoom\Bulletin.md
4. 向用户确认"工作间规范已加载，随时可以开始"
未执行以上步骤 = 会话无效。

【单一事实源】本注入层不重复维护工作间内容；
项目清单、个人信息、设备环境、文档规范一律以 1_Memory/ 为准，冲突时以工作间为准。

【日志路径】工作日志写入 4_Logs\WorkingLog\WorkingLog_YYYY-MM_[本智能体名].md

【智能体专属规则】（仅与自身运行环境相关的规则，可选）
```

## 五、维护与审查

1. **本指引由助理智能体维护**（规范制定属办公室主任职责），修订记录见文末。
2. 各智能体接入或变更注入层后，应在 `3_MeetingRoom/Letters/` 向协调器协调者报备，并更新第三章状态列。
3. 工作间重大结构调整（如再次更名/迁移）时，需同步检查所有智能体注入层的指针是否失效——**这是本方案唯一需要人工盯守的环节**。
4. 建议每季度抽查一次各智能体新会话是否真正执行了启动指令。
