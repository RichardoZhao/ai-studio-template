# 全局公告板

> **规则**：追加式，最新在最前。每次会话启动必读。
> 格式：`### [标签] YYYY-MM-DD HH:MM @署名`

---

## 条目格式模板

以下为 Bulletin 中常见的条目类型及格式规范。新条目严格按对应模板撰写。

---

### 1. 状态更新 `[状态更新]`

```
### [状态更新] 简述 — YYYY-MM-DD HH:MM @署名

进展说明（1-3 句话）。

- ✅ 已完成项
- ⏳ 进行中项
- ❌ 阻塞项

**下一步**：[行动说明]

详见：[相关文件路径]（可选）
```

---

### 2. 审核请求 `[审核请求]`

```
### [审核请求] 任务名称 @审核人 — YYYY-MM-DD HH:MM @Hermes

方案文件：`MeetingRoom/Conclusions/[任务名]_最终实施方案_vX.Y.md`
审核人：[审核人]
```

## 协议级规则（不可省略）

### 智能体称呼（示例，按实际修改）

| 智能体 | 称呼 | 角色 |
|--------|------|------|
| （示例）主智能体 | 协调者 | 总调度/技术执行官 |
| （示例）副智能体 | 助理 | 文案与文档 |
| （示例）业务智能体 | 市场 | 业务与运营 |
| （示例）编码智能体 | 码农 | 代码编写 |

### 审核流程（S 级任务强制）

负责者写奏折 → 放入 `MeetingRoom/Conclusions/` → 通知 Bulletin → 审核者审阅 → 通过签字 / 封驳打回

### 讨论流程（三方及以上）

Hermes 启动讨论 → 创建 `Discussions/[主题]_YYYY-MM-DD.md` → 各智能体轮次发言 → 三方通过 → Hermes 出总结

### 公告板纪律

1. **追加，不修改**：新条目追加在文件顶部（最新在最前），不修改历史条目
2. **签名必署**：每条条目末尾标明署名和时间
3. **引用用相对路径**：引用 MeetingRoom 内部文件用相对路径（如 `Discussions/xxx.md`），引用外部文件用绝对路径
4. **不广播小事**：点对点通信走 `Letters/`，不要在 Bulletin 广播
5. **同一条目不重复发**：发布前检查是否已有重复条目
