# 多智能体通信协议 v1.2

> 生效日期：2026-07-03 | 起草：助理智能体 | 会审：Hermes | 状态：待使用者审批
>
> 本协议定义使用者麾下所有智能体之间的协作规则。
> **零依赖、纯文件系统、不安装任何新平台。**
>
> v1.1 核心变更：指挥链集中化（Hermes 总调度）、角色定位修正、目录结构优化、自动对话协议。
> v1.2 核心变更：助理智能体→办公室主任、业务智能体→市场部经理、Mailbox→MeetingRoom, 以最新文件夹体系为准。

| 代号 | 角色 | 平台 | 环境 | 环境限制 | 核心职能 |
|------|------|------|------|---------|---------|

## 二、指挥链

```
使用者（最终决策者）
    │
    ├── Office 类任务 ──────→ WorkBuddy 直接执行，完成后 Bulletin 知会
    │
    └── 其他所有任务 ──→ Hermes（总调度）
                            │
                    拆解、分派、指定审核人
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
         WorkBuddy       Wukong        Codex
         （执行）        （执行）       （执行）
              │             │             │
              └─────────────┼─────────────┘
                            ▼
                    交付物 / 奏折
                            │
                    审核人（Hermes 指派，Bulletin 公示）
                         ├── 通过 → 交付使用者
                         └── 封驳 → 打回修改
```

### 2.1 例外规则

| 场景 | 流程 |
|------|------|
| **Office 三件套 + PDF** | 使用者直接指令 WorkBuddy，不走 Hermes 调度。完成后在 Bulletin 追加 `[状态更新] 任务名 - 已完成 @WorkBuddy` |
| **紧急任务** | 使用者直接指派任何人，无需经过调度链 |
| **使用者说「你俩聊」** | 进入自动对话模式（见 3.3 节） |

## 三、通信中枢

### 3.1 目录结构

```
MeetingRoom\
├── Bulletin.md                               ← 全局公告板
├── Discussions\                              ← 多方讨论（按主题）
│   └── [主题]_[YYYY-MM-DD].md
├── Letters\                                  ← 点对点信箱
│   ├── Hermes vs Workbuddy (YYYY-MM-DD).md   ← Hermes↔助理智能体
│   ├── Hermes vs Wukong.md                    ← Hermes↔业务智能体
│   ├── Hermes vs Codex.md                     ← 预留
│   └── Workbuddy vs Codex.md                  ← 预留
├── 奏折\                                      ← S 级任务奏折存放
│   └── README.md                              ← 使用说明
└── Archive\                                   ← 历史归档
    └── Bulletin_YYYY-MM.md                    ← 公告板月度归档
```

### 3.2 Bulletin.md — 全局公告板

| 属性 | 规则 |
|------|------|
| **目的** | 广播通知、任务分配公示、项目状态、决策记录 |
| **写入者** | 使用者（发布指令）、任何智能体（报告状态变更、请求裁决） |
| **读取者** | **所有人每次会话启动必读** |
| **格式** | 追加式，最新在最前。格式：`### [标签] YYYY-MM-DD HH:MM @署名` |
| **标签** | `@all`（全员）、`@Hermes` / `@WorkBuddy` / `@Wukong` / `@Codex`（指派）、`请求裁决`、`状态更新`、`决策记录`、`审核公示` |
| **归档** | 每周日由 WorkBuddy 归档超 7 天已关闭条目至 `Archive\Bulletin_YYYY-MM.md` |

### 3.3 Letters — 点对点信箱

| 属性 | 规则 |
|------|------|
| **格式** | 追加式，每条标注时间+署名，只追加不删除 |
| **署名格式** | `助理智能体 YYYY-MM-DD HH:MM` / `Hermes YYYY-MM-DD HH:MM` |
| **超 300 行** | 新建续写文件 |
| **自动对话** | 使用者说「你俩聊」时触发——双方各自轮询信箱，看到新消息即回复，直到使用者叫停或话题结束 |

**自动对话参数**：

| 参数 | Hermes | WorkBuddy | Wukong |
|------|:--:|:--:|:--:|
| 轮询间隔 | 30 秒 | 30 秒 | 30 秒 |
| 发言顺序 | Hermes → 助理智能体 → 业务智能体，循环 | 同上 | 同上 |
| 触发条件 | 使用者指令 "你俩聊" 或 "你们仨聊" | 同上 | 同上 |
| 停止条件 | 使用者说停 / 所有参与方确认话题结束 | 同上 | 同上 |
| 日常非对话模式 | 不轮询，使用者叫谁谁查信 | 同上 | 同上 |

### 3.4 Discussions — 多方讨论

| 属性 | 规则 |
|------|------|
| **触发** | 一个话题需要三方以上智能体参与 |
| **启动** | 使用者指令，或任意智能体在 Bulletin 提议 |
| **文件** | `Discussions\\[主题]_[YYYY-MM-DD].md` |
| **格式** | 追加式 Markdown，按署名顺序发言 |
| **独立意见存档** | 各方提交的完整报告/独立意见，以 `[主题]_[署名]版[_YYYY-MM-DD].md` 另存为独立文件，与讨论主文件并列存放，便于追溯对比，不混入追加内容 |

## 四、任务流转机制（三省制）

> 门下省审核的详细格式与流程，见独立文件：《门下省审核细则 v1.0》

```
使用者 或 Hermes 分派任务
    │
    ▼
负责智能体产出初稿
    │
    ▼
【S 级任务】撰写「奏折」
    │
    ▼
审核智能体检视（Hermes 指派，Bulletin 公示）
    ├── 通过（签字） → 交付使用者
    └── 封驳（打回） → 修改后复审
```

### 4.1 审核规则

| 规则 | 说明 |
|------|------|
| **审核必强制** | S 级任务（交付使用者的正式文档/代码/设计）必须先经另一智能体审核 |
| **审核者不可为原作者** | 谁产出谁不能审自己 |
| **审核人由 Hermes 指派** | 在 Bulletin 公示：审核人、时限、审核标准 |
| **驳回必附理由** | 按「封驳格式」写明具体问题（见审核细则） |
| **复审** | 修改后重新提交审核，流程同上 |
| **奏折存放** | `MeetingRoom\奏折\[任务名]_[负责者]_[YYYYMMDD].md` |
| **审核时效** | 常规 S 级 8 小时内，超时需在 Bulletin 说明 |
| **格式检查** | 审核时一并检查格式（不设独立预审环节） |

### 4.2 任务分级

| 级别 | 定义 | 审核要求 |
|:--:|------|:--:|
| **S** | 交付使用者的正式文档/代码/设计 | **强审**：奏折 + 门下省签字 |
| **A** | 内部协作产出（建议草稿、日志） | 推荐审核（可省略奏折） |
| **B** | 信息查询 / 简单操作 | 无需审核 |

## 五、例行协作流

### 5.1 每日启动（每个智能体必做）

1. 读 `Bulletin.md`（最新任务、状态变更）
2. 读自己信箱最后一条（看是否有新通信）
3. 读工作日志恢复上下文

### 5.2 任务完成后

| 任务类型 | 操作 |
|------|------|
| Office 类 | 直接交付使用者 + Bulletin 发 `[状态更新]` |
| S 级 | 写奏折 → 通知审核人 → 审核通过后交付使用者 |
| A/B 级 | 通知分派人或直接回复使用者 |

### 5.3 遇到问题

1. 自行解决 → 记录工作日志
2. 需另一智能体协助 → 写 Letters/
3. 需使用者裁决 → Bulletin 发 `请求裁决`
4. 需多方讨论 → Bulletin 提议 + Discussions/

## 六、文件管理规范

| 规范 | 详情 |
|------|------|
| **命名** | 英文单词全称、首字母大写（Chapter、Appendix、Source、Draft），禁用缩写 |
| **信箱上限** | 单文件超 300 行 → 新建续写文件 |
| **公告板归档** | 每周日 WorkBuddy 归档超 7 天已关闭条目 |
| **历史归档** | 超 30 天不活跃通信文件 → `Archive/` |
| **互不侵犯** | 不删除对方文件；不修改对方工作间 `1_Memory/` |
| **编码** | UTF-8，无 BOM |
